# Contributing

Only Prem-Tomar merges to master. Use a branch/fork and PR targeting master, with task ID in the branch name.

The [learning rules](docs/LEARNING_RULES.md), [review format](docs/REVIEW_GUIDE.md) and [Question of the Day](docs/QUESTION_OF_THE_DAY.md) are mandatory. W1 D7 follows D1-D6, in order, for each contributor. Preserve later work on its branch while its earliest unreviewed prerequisite is completed.

Follow the roadmap's complementary feature asks, predict behavior independently, and reuse accepted units. Each learner demonstrates every assigned concept and mastery variation. PR/session evidence is sufficient; the reviewer records ledger evidence.

## PR requirements

- Task ID and personal issue when issue creation is authorized.
- Concrete behavior, purpose, alternatives, and tradeoffs.
- Reproducible acceptance/failure behavior or experiments; test-writing feedback is optional.
- One primary idea, bounded implementation and explicit exclusions; introduce only necessary abstractions and use research-oriented hints.
- Separate learning evidence and concepts for reviewer ledger updates, with assistance and unassessed gaps recorded honestly.
- Hints used and reciprocal review; short coaching/walkthrough evidence is sufficient, without a required formal report.
- No secrets, credentials, real customer data, or unverified claims.

Run python scripts/validate_curriculum.py. Run phase-appropriate application checks/builds and native verification as tooling exists. Tests and documentation are not standalone issue assignments or mandatory authoring deliverables; reviewers may suggest meaningful tests with hints and expected behavior in feature PRs.

Review does not grant merge permission. Do not change governance or activate issue generation without the owner's explicit instruction.

Accept implementation against its stated product goal. Mastery and Question of the Day answers are tracked separately: from D2, revisit earlier completed work and answer every part in your own words in the review discussion. The reviewer preserves the original answer, corrects specific gaps and asks a targeted follow-up. An unanswered learning question does not itself block an otherwise correct PR; defects in the original code contract still do. Both learners must independently pass mastery gates before forecast advancement.
