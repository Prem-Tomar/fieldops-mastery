# Contributing

Only Prem-Tomar merges to master. Use a branch/fork and PR targeting master, with task ID in the branch name.

Follow the roadmap's complementary feature asks, predict behavior independently, and reuse accepted units. Each learner demonstrates every assigned concept and mastery variation. PR/session evidence is sufficient; the reviewer records ledger evidence.

## PR requirements

- Task ID and personal issue when issue creation is authorized.
- Concrete behavior, purpose, alternatives, and tradeoffs.
- Reproducible acceptance/failure behavior or experiments; test-writing feedback is optional.
- Personal concept demonstration and concepts for reviewer ledger updates.
- Hints used, reciprocal review, and coach assessment.
- No secrets, credentials, real customer data, or unverified claims.

Run python scripts/validate_curriculum.py. Run phase-appropriate application checks/builds and native verification as tooling exists. Tests and documentation are not standalone issue assignments or mandatory authoring deliverables; reviewers may suggest meaningful tests with hints and expected behavior in feature PRs.

Review does not grant merge permission. Do not change governance or activate issue generation without the owner's explicit instruction.
