# JS-03 — Debounce search and prevent stale responses

Phase: P01 | Order: 3 | Prerequisite: JS-02

## Precise task

Simulate searches for pump then motor. Make pump resolve last. Add a 250 ms debounce, cancel pending timers, and ensure only the latest query can display results or errors. Empty queries clear results.

## Why we are doing this

Network completion order must not determine the current UI.

## What you achieve

A search controller that remains correct under rapid typing and delayed responses.

## What this teaches

- promises
- async await
- closures
- timers
- race conditions
- AbortController
- errors
- cleanup

## Progressive hints

1. Trace query generation and response arrival separately.
2. Cancellation and permission to update state solve different problems.
3. Use controllable promises and fake time rather than random delays.

## Acceptance criteria

- [ ] Check reversed responses, stale failures, empty queries, and disposal.
- [ ] No callback updates state after disposal.
- [ ] Explain why debouncing alone cannot prevent a stale response.
