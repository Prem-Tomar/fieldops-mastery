# JS-04 — Implement bounded asynchronous work

Phase: P01 | Order: 4 | Prerequisite: JS-03

## Precise task

Implement runTasks(tasks, limit, signal) for 20 asynchronous jobs with concurrency limit 3. Preserve input order in returned success/error results. Cancellation prevents new jobs starting; document how already-started jobs cooperate with the signal.

## Why we are doing this

Unbounded concurrency creates overload and unpredictable failures.

## What you achieve

A bounded runner and a clear cancellation contract.

## What this teaches

- event loop
- microtasks versus timers
- promise combinators
- error propagation
- concurrency versus parallelism
- resource cleanup

## Progressive hints

1. Track active jobs and the next index separately.
2. Decide whether one failure stops the batch before choosing a combinator.
3. Predict a trace containing a promise, a timer, and synchronous code.

## Acceptance criteria

- [ ] Peak active jobs never exceeds three; invalid limits are rejected.
- [ ] One rejected job follows the documented policy and produces no unhandled rejection.
- [ ] Cancellation stops new work and all started work is observed.

## Independent mastery challenge
