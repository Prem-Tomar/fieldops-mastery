## What this teaches

- **SSE versus WebSockets:** SSE sends a server-to-client event stream; WebSockets provide a bidirectional connection with different protocol needs. Example: Choose a transport for live dispatch updates.
- **ordering:** Ordering defines which sequence guarantees consumers can rely on. Example: Specify whether job events are ordered per job or globally.
- **cursors:** A cursor identifies a continuation position in results or event history. Example: Resume updates after the last processed event.
- **deduplication:** Deduplication recognizes repeated work or events and avoids repeated effects. Example: Ignore a duplicate accepted-completion event.
- **reconnect:** Reconnect restores a broken connection and may require application-state recovery. Example: Reconnect and replay missed updates before marking the board current.
- **authentication:** Authentication establishes identity; authorization decides whether that identity may perform an action. Example: A logged-in technician still cannot edit another tenant's job.
- **snapshot plus event stream:** A snapshot gives current state; an event stream carries changes. Their boundary must avoid a gap. Example: Fetch a snapshot with a compatible stream cursor.
