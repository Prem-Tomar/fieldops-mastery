# RT-03 — Stream a large report with backpressure

Phase: P08 | Order: 31 | Prerequisite: RT-02

## Precise task

Export one million generated job rows to CSV while a deliberately slow client downloads it. Bound memory, support cancellation, escape CSV fields safely, and clean up the database cursor on disconnect.

## Why we are doing this

Large responses expose memory, event-loop, and resource-management mistakes.

## What you achieve

A streaming export that does not accumulate the entire result.

## What this teaches

- Node streams
- backpressure
- pipeline
- async iterators
- buffering
- database cursors
- CSV correctness
- cancellation

## Progressive hints

1. Measure retained memory while slowing the consumer.
2. Inspect where data can accumulate between producer and client.
3. Define handling of CSV formula-leading values for spreadsheet consumers.

## Acceptance criteria

- [ ] Memory stays within a declared budget on documented hardware.
- [ ] Disconnect closes owned database and stream resources.
- [ ] Concurrent lightweight requests remain within the agreed latency budget.
