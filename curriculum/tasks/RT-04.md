# RT-04 — Offload CPU work and shut down gracefully

Phase: P08 | Order: 32 | Prerequisite: RT-03

## Precise task

Add a CPU-heavy scheduling simulation. Compare execution on the main thread and in a bounded worker pool. On shutdown stop admission, drain or persist accepted work, and close connections within a documented deadline.

## Why we are doing this

Async syntax does not prevent synchronous CPU work from blocking Node.

## What you achieve

A measured execution strategy and predictable process termination.

## What this teaches

- event-loop delay
- worker_threads
- pool sizing
- CPU versus I/O
- message serialization
- signals
- graceful shutdown
- timeouts

## Progressive hints

1. Profile CPU use and event-loop delay before offloading.
2. Account for worker startup and serialization cost.
3. Define what accepted means before choosing shutdown behavior.

## Acceptance criteria

- [ ] Compare unrelated API latency and throughput for both implementations.
- [ ] The worker queue is bounded and overload has an explicit response.
- [ ] A shutdown simulation loses no durably acknowledged job.
