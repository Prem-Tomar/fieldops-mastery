## What this teaches

- **event-loop delay:** Event-loop delay measures how long scheduled JS work is delayed by runtime load. Example: Compare API responsiveness during a synchronous calculation.
- **worker_threads:** Worker threads run JavaScript in separate execution contexts for suitable CPU work. Example: Offload a scheduling simulation to a bounded pool.
- **pool sizing:** Pool sizing balances concurrency against CPU, memory, and queue overhead. Example: Too many CPU workers can reduce useful throughput.
- **CPU versus I/O:** CPU work calculates; I/O waits for external resources. They require different scaling strategies. Example: A report calculation and a database wait are different bottlenecks.
- **message serialization:** Serialization converts values into a representation another process or storage can consume. Example: A worker message must represent its payload safely.
- **signals:** Process signals notify software about lifecycle or other operating-system events. Example: Handle termination by stopping admission and draining accepted work.
- **graceful shutdown:** Graceful shutdown stops new work and safely finishes or persists accepted work before exiting. Example: Do not lose acknowledged worker jobs during deployment.
- **timeouts:** A timeout bounds waiting but may leave an uncertain outcome if work committed elsewhere. Example: A timed-out completion might still have succeeded.
