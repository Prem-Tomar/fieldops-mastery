# TS-01 — Encode job-state invariants

Phase: P02 | Order: 5 | Prerequisite: JS-04

## Precise task

Under strict TypeScript settings, model draft, assigned, inProgress, completed, and cancelled jobs. Assigned jobs require technicianId; completed jobs require completion evidence. Implement availableActions(job) with exhaustive state handling. Include four small compiler experiments for primitive annotations, typed arrays, tuples, and an enum versus a literal union.

## Why we are doing this

Contradictory domain objects should be difficult to construct.

## What you achieve

State-specific contracts and compile-time examples of illegal objects.

## What this teaches

- type inference
- interfaces and type aliases
- optional properties
- literal types
- unions and intersections
- discriminated unions
- narrowing
- never

- primitive annotations
- array and tuple types
- enum versus literal union

## Progressive hints

1. Use status as a discriminator.
2. Check where optional fields allow contradictions.
3. Use intentional compiler-error fixtures and an exhaustive branch.

## Acceptance criteria

- [ ] Illegal completed and assigned objects fail compilation.
- [ ] Every state has an explicit action policy.
- [ ] No any or unchecked assertion is used to bypass domain validation.
