## What this teaches

- **type inference:** TypeScript often derives a value's type from its expression and context. Example: A numeric initializer can infer number without an explicit annotation.
- **interfaces and type aliases:** Both describe types; aliases can also name unions and other type expressions. Example: Use a Job alias for a union of state-specific object types.
- **optional properties:** An optional property may be absent; absence is not always interchangeable with a supplied undefined. Example: Distinguish a missing notes field from an explicitly cleared value.
- **literal types:** A literal type allows one exact value rather than every value of its primitive type. Example: status:'completed' identifies a particular job variant.
- **unions and intersections:** A union accepts one of several shapes; an intersection combines requirements. Example: Job is a union; a tenant-scoped entity can intersect with {tenantId:string}.
- **discriminated unions:** A union has a shared tag whose value identifies which object shape applies. Example: status:'completed' narrows the job to a shape with evidence.
- **narrowing:** Checks refine a broad type into a more specific type within a branch. Example: Check typeof input === 'number' before numeric operations.
- **never:** never describes a value that cannot occur, useful for unreachable and exhaustive branches. Example: An exhaustive status switch assigns its impossible remainder to never.
- **primitive annotations:** TypeScript annotations describe allowed primitive values at compile time. Example: quantity:number rejects a string in checked TypeScript code.
- **array and tuple types:** An array repeats an element type; a tuple describes specific positions and their types. Example: [string,number] can represent [jobId,quantity].
- **enum versus literal union:** An enum names related constants; a literal union limits values to specific alternatives. Example: 'draft' | 'completed' restricts a job status without an enum object.
