## What this teaches

- **generics:** Generics parameterize a type or function while preserving relationships between input and output types. Example: Page<Job> retains Job as the item type.
- **constraints:** A generic constraint limits which types a parameter accepts. Example: K extends keyof T restricts a projection to valid property keys.
- **keyof:** keyof produces the union of a type's property names. Example: keyof Job can restrict permitted field selections.
- **indexed access:** Indexed access extracts a property or collection element type from another type. Example: T[K] describes the selected field's value type.
- **mapped types:** A mapped type transforms properties according to a rule. Example: Create a readonly view from every property of a domain object.
- **conditional types:** A conditional type selects a type result based on a type relationship. Example: Extract the success value from Result<T,E>.
- **utility types:** Built-in helpers transform types for common needs. Example: Pick<Job,'id'|'status'> selects two fields.
- **structural typing:** Compatibility depends largely on shape rather than a type's declared name. Example: Two objects with required id/status fields may be compatible.
- **readonly:** readonly prevents certain mutations through a TypeScript reference; it does not freeze runtime objects. Example: Readonly<Job> is a compile-time view.
- **function types:** A function type specifies parameters and return type, including callback contracts. Example: A listener accepts a JobEvent and returns void.
- **overloads:** Overloads describe distinct supported calling shapes while sharing one implementation. Example: A lookup can accept one ID or an array with matching return contracts.
- **optional and rest parameters:** Optional parameters can be omitted; rest parameters collect a variable number of arguments. Example: A logger accepts an optional context and additional message values.
