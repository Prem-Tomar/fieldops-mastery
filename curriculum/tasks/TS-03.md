## What this teaches

- **unknown versus any:** unknown requires checking before use; any bypasses many compiler guarantees. Example: Accept network input as unknown and validate it.
- **type guards:** A predicate or checked condition narrows a type by establishing a property. Example: isJobCommand verifies required command fields.
- **runtime schemas:** A runtime schema checks actual data shapes; static types alone do not inspect incoming JSON. Example: Reject a quantity string at the API boundary.
- **narrowing:** Checks refine a broad type into a more specific type within a branch. Example: Check typeof input === 'number' before numeric operations.
- **typed errors:** Explicit error shapes make failure handling predictable without relying on message text. Example: Return {code:'CONFLICT'} for a rejected state transition.
- **null and undefined:** null commonly represents an explicit empty value; undefined often represents absence or an uninitialized result. Example: An API must define whether omitted and null fields differ.
- **serialization:** Serialization converts values into a representation another process or storage can consume. Example: A worker message must represent its payload safely.
