# TS-04 — Define versioned web and mobile contracts

Phase: P02 | Order: 8 | Prerequisite: TS-03

## Precise task

Define v1 and v2 job response contracts and explicit conversion to an internal domain model. v2 adds approval status while v1 clients retain their documented behavior. Enable strict, noUncheckedIndexedAccess, and exactOptionalPropertyTypes.

## Why we are doing this

Client versions evolve at different speeds.

## What you achieve

A shared contracts package plan with explicit compatibility boundaries.

## What this teaches

- strict compiler options
- exhaustiveness
- type-only imports
- module boundaries
- declaration output
- type compatibility
- runtime versus compile-time contracts

- tsconfig
- source maps
- TypeScript compilation versus execution

## Progressive hints

1. Keep wire DTOs separate from domain objects.
2. Define absent versus null fields.
3. Test the contract that an older client actually consumes.

## Acceptance criteria

- [ ] Both version fixtures parse and map correctly.
- [ ] A missing map lookup and an incorrectly supplied optional value are caught or handled.
- [ ] Explain why a shared TypeScript package does not prove deployed clients are compatible.
