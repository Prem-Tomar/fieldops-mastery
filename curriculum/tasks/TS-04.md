## What this teaches

- **strict compiler options:** tsconfig controls compilation and checks; strict options expose unsafe assumptions. Example: Enable strict and noUncheckedIndexedAccess for missing lookups.
- **exhaustiveness:** Every declared variant must be handled; adding a variant should expose missing decisions. Example: Add awaitingApproval and find incomplete status switches.
- **type-only imports:** Type-only imports carry compile-time information and can be removed from emitted JavaScript. Example: import type {Job} avoids treating Job as a runtime value.
- **module boundaries:** Public interfaces separate packages; consumers use exported behavior without depending on a module's internal details.
- **declaration output:** Declaration files publish type information for consumers of compiled packages. Example: A contracts package emits .d.ts files.
- **type compatibility:** A type is compatible when it can be used safely where another type is expected under compiler rules. Example: A narrowed completed job can be used as a general job.
- **runtime versus compile-time contracts:** Compile-time contracts check source code; runtime contracts check deployed interactions and actual data. Example: A typed mobile client can still receive malformed JSON.
- **tsconfig:** tsconfig controls compilation and checks; strict options expose unsafe assumptions. Example: Enable strict and noUncheckedIndexedAccess for missing lookups.
- **source maps:** Source maps relate generated code locations to original source for debugging. Example: Trace a production stack frame back to its TypeScript line.
- **TypeScript compilation versus execution:** TypeScript checks/transforms source; the runtime executes JavaScript and does not automatically enforce annotations. Example: A compiled API still needs JSON validation.
