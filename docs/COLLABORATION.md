# Two-person learning agreement

Both developers complete all 44 tasks and every catalog concept, including basics. Experience changes guidance and challenge depth, not coverage.

## Shared product, independent knowledge

- Each person has individual task instances, evidence, ledger, and scores.
- Independently predict behavior and attempt isolated implementation before comparing.
- Integrate production behavior once. Alternate shared integration driver/reviewer each task.
- Second PR contributes tests, validated alternatives, investigation, or personal evidence. Approval alone does not prove implementation knowledge.
- Both own frontend, native, backend, data, security, and architecture work.
- Assisted pair work remains assisted until reproduced independently.
- The 5-year learner critiques senior assumptions; the 10-year learner implements basics and accepts corrections.
- Spikes: experiments/<learner>/<task-id>/. Evidence: evidence/<learner>/<task-id>.md.

Odd task: 5-year learner drives shared integration. Even task: 10-year learner drives. Swap for availability with a recorded reason while maintaining balanced ownership.

Prem-Tomar supplies both GitHub handles before assignment. Role folders are placeholders, not permission tiers.

## Coach responsibilities

Write expected behavior before seeing solutions. Introduce an undisclosed variation within scope. Distinguish business-policy choices from bugs, reproduce findings, and accept justified alternatives.

Assess the coach's scenario quality, reproducibility, fairness, and willingness to revise an incorrect expectation. Both learners must pass shared phase gates independently.
